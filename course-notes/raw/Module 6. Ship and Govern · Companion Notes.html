Reference Card

Frameworks Reference Card

1. The core reframe

Autonomy is a product decision per user segment, not one global setting. You ship the dial; context sets the level.

It's "a trust problem, not a tooling problem" (Elena Verna). The config to grant autonomy is one change away, the right to grant it is earned.

2. The Autonomy Dial (M6)

Tesla-driver vs. Waymo-passenger, a metaphor for how much control a user wants to keep, not a claim about whose deployment is safer.

Segment appetiteDesired autonomyWhy
Tesla-driver (wants control)Low, suggest, human actsHands near the wheel; every action confirmable
In-between (cautious but willing)Medium, acts, human approvesTrust building; checkpoints still fire
Waymo-passenger (hand it over)High, acts within boundsTrust established; convenience over control

The dial doesn't move the M1 Agent Line, it sets how many below-the-line actions still pause at an M5 HITL checkpoint, for this user.

3. The Trust Ladder (M6): earn each rung

RungAgent doesHuman's role
1 · ShadowRuns silently; output logged, never usedCompares would-be actions to reality
2 · AssistedSuggests; output shownActs (or not) on the suggestion
3 · SupervisedActs, but each action waitsApproves every action
4 · Bounded-autonomousActs within bounds, no per-action approvalSpot-checks samples; reviews exceptions
5 · AutonomousActs; humans notified, not askedMonitors dashboards & incidents

Each rung is gated by M5 eval results + a clean incident record. "'Trust us' is no longer enough" (Ajit Varma). No eval gate, no climb. A trust incident knocks you back a rung. Climb slow, descend fast.

4. Cortex on the ladder

RungCortex behaviour
ShadowDrafts status updates into a log nobody posts; measure would-be accuracy
AssistedDraft appears in compose window; measure edit distance / acceptance
SupervisedPreps full story batch package; eng lead approves each send
Bounded-autonomousSends low-risk updates (no commitments/$) within bounds; weekly spot-check
AutonomousOwns routine status-update lane; humans watch dashboards

Posting an unapproved company-wide update never gets a rung, the Agent Line keeps it human, always.

5. Deployment beyond the prototype

"Export the flow" is not a deploy. Pick a runtime (tool-agnostic):

RuntimeBest when
Managed agent platformSpeed + built-in monitoring over control
Serverless functionsEvent-driven, bursty (hook loops); pay-per-run
Always-on service / containerHeartbeat/cron loops, persistent state, full control

The operator handoff: what turns a deploy into something a team can run:

ElementAnswers
RunbookHow to operate, pause, recover it
On-call ownerWho gets paged; named, not "the team"
Rollback planHow to get back to known-good, fast
Monitoring dashboardHow to see it's healthy without reading logs

Test: if the builder went on vacation tomorrow, would the deploy survive?

6. Measuring ROI beyond adoption & tokens

Adoption = they clicked it. Tokens = it ran (and tokens are a cost). Measure value instead:

CategoryMetricCortex example
OutcomeTask completion · time saved · error/incident rate% threads resolved end-to-end vs. shadow baseline
Cost-to-serveFully-loaded cost per completed taskModel + tools + retries + human review per resolved thread
Trust incidentsCount & severity of out-of-bounds / trust-loss eventsThe metric that freezes the Trust Ladder

"Cortex completed N% of routine threads, saving ~X hrs/wk at $Y cost-to-serve, with Z trust incidents." Can't fill the blanks? You're reporting activity, not value.

7. The agentic-era operating model

Signal (Meaghan Choi, Anthropic, ProductCon 2026): small pods of builders + a fleet of agents; non-engineers shipping to production. Your shift: from designer of one agent to operator of an agent system: setting dials, owning rungs, watching dashboards. Hold it loosely; it's a direction, not a settled model.

Glossary

Glossary

TermDefinition
The Autonomy DialThe M6 framework: autonomy is a product decision set per user segment, not one global level. You ship the dial; context and segment set where it points.
Autonomy levelHow much an agent acts on its own for a given user or task, set by the dial, from suggest-only to fully autonomous within bounds.
Segment (autonomy)A group of users whose appetite for control differs, and who therefore get a different dial setting for the same agent.
Tesla-driver (metaphor)A user who wants to keep their hands near the wheel, Cortex suggests, they decide and act. A metaphor for low desired autonomy, not a claim about deployment safety.
Waymo-passenger (metaphor)A user who hands the whole task over, Cortex acts within bounds, they check in occasionally. A metaphor for high desired autonomy.
The Trust LadderThe M6 framework for widening autonomy in earned rungs: shadow → assisted → supervised → bounded-autonomous → autonomous. Each rung gated by evals + incident record.
Shadow (rung 1)The agent runs silently on real inputs; output is logged but never used. Lets you measure would-be accuracy at zero risk before launch.
Assisted (rung 2)The agent suggests an action and shows its output; the human acts (or doesn't). You measure acceptance and edit distance.
Supervised (rung 3)The agent acts, but every action waits for explicit human approval before it executes.
Bounded-autonomous (rung 4)The agent acts within defined bounds without per-action approval; the human spot-checks samples and reviews escalated exceptions.
Autonomous (rung 5)The agent acts and humans are notified, not asked; oversight is via dashboards and incident review.
Eval gateA pre-declared bar, pass rate, error rate, policy-violation rate over a real window, that an agent must clear (using M5 evals) before climbing the next Trust Ladder rung.
Incident recordThe log of trust incidents over a window; a clean record is a required gate to climb a rung, and a new incident knocks the agent back down.
Trust incidentA logged event where the agent acted outside bounds or lost a user's confidence. The metric that freezes the dial and gates the ladder.
Operator handoffThe package that turns a deploy into something a team can run: runbook, on-call owner, rollback plan, monitoring dashboard. Distinct from a prototype link.
RunbookThe documented procedure for operating, pausing, and recovering a live agent, not "ask the person who built it."
On-call ownerThe named person (and escalation path) responsible when the agent breaks. "The team" is not an owner.
Rollback planThe defined path back to a known-good state, revert a prompt/version, disable a tool, or drop the dial a rung, executable fast.
Monitoring dashboardThe live view of an agent's health (eval pass %, escalation rate, cost-to-serve, incidents) so you don't have to read raw logs.
RuntimeWhere the agent actually runs in production, a managed agent platform, serverless functions, or an always-on service/container. Chosen by loop type and control needs.
Managed agent platformA hosted service that runs, scales, and observes agents for you, trades control for speed and built-in monitoring.
Cost-to-serveThe fully-loaded cost of one completed task (model calls, tools, retries, human review), the business-case number, as opposed to raw token spend.
Outcome metricsROI measures of whether the agent did the job: task completion rate, time saved (vs. shadow baseline), and error/incident rate.
Adoption / token trapThe mistake of reporting that people used the agent or that it consumed tokens as if those were value. Adoption is activity; tokens are a cost.
Agentic-era operating modelThe emerging shape of small pods of builders running a fleet of agents, with non-engineers shipping to production, and the PM as operator of the system.
PM as operatorThe M6 role shift: from designing one agent to operating a system of them, setting dials across segments, owning ladder rungs, watching dashboards.
production-and-autonomy.mdThe M6 capstone repo artifact: Autonomy Dial by segment, Trust Ladder position + gate, deployment plan, ROI metrics, and the widen-autonomy decision rule.
Final Project Deliverables BuilderThe course tool that turns your M1 to M6 artifacts into a shareable HTML pitch deck plus a clean README, fill the fields, preview live, and download both. Includes a worked "Load Cortex example" fallback.
